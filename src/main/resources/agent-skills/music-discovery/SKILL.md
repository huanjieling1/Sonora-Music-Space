# 音乐发现

1. 用户给出足够的搜索或推荐意图后立即调用 `recommendMusic`；歌曲、专辑、曲风、情绪、活动或场景中的任意一种即可执行。若用户目标是歌手或乐队本身的头像、简介、生涯、成就、曲风及完整目录，改用 `qq-artist-discovery`。
2. “把 X 的歌曲给我听”“播放 X 的音乐”“找 X 的原声/OST/配乐”等请求必须视为明确的歌曲请求。X 可以是游戏、影视、动画、赛事、角色、作品系列或其他专有名称；先原样保留 X 调用 `recommendMusic`。若用户明确要求听或播放，再交给 `music-playback` 播放第一首可靠结果。
3. “找一些 Re:0 的歌”“来点进击的巨人相关音乐”使用 `recommendMusic`；“找一个跟无畏契约相关的歌单”明确要求现成公开歌单，必须改用 `qq-public-playlists` 的 `searchQqPlaylists`，不得用歌曲列表冒充歌单。
4. 必须区分“明确搜索”和“开放推荐”。明确搜索含具体歌名、歌手、专辑、作品或专有名称，只提取用户原话中的关键词，保留大小写与原始写法，不得翻译、补全别名或追加限定词。例如“找一些 Re0 的歌”只能提交 `Re0`，“我想听 lol 的歌”只能提交 `lol`。
5. “给我推荐一些歌”“来点适合我的”“按我的口味推荐”“适合跑步的音乐”等属于开放推荐。必须让 `recommendMusic` 读取音乐画像，把当前场景作为最高优先级，并结合可靠的明确偏好和行为推断生成候选搜索方向；不得把“歌曲推荐”“音乐推荐”等指令词当成 QQ 搜索关键词。
6. 推荐说明必须明确区分当前需求、画像偏好、需要避开的内容和冷启动状态。画像为空或证据不足时要说明使用热门内容或探索性推荐，不得虚构用户喜好。
7. 根据会话记忆解析简短追问。逐字保留所有专有名称和硬约束；不得擅自增加用户没有提供的年份、赛事、官方属性或专辑。
8. 当前请求中的明确约束始终高于画像；画像只能用于补充召回和有界调整排序，不能覆盖用户当下说“不想听”或点名要听的内容。
9. 仅搜索或推荐的请求只能展示结果，不得自动开始播放。
10. 下一页、上一页或指定结果页使用 `loadMusicResultsPage`。页码从 1 开始且最多 20 页；不得虚构尚未加载的页面内容。
11. 工具已经通过结构化 Action 展示音乐卡片时，最终回复只需用一到两句话总结推荐方向和画像依据，不要在文字中重复罗列全部歌曲。
